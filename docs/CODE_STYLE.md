# 代码风格（项目版）

目标：让刚接触项目的人能从上到下读懂每一步在做什么、为什么这样做。

1. **减少封装**：只有职责独立、确实有复用价值的逻辑才单独封装；不要把简单流程拆成一堆小函数。
2. **减少修饰和包装**：不滥用装饰器、类、继承、静态方法、属性包装、上下文管理器。保留有实际必要的设计。
3. **减少嵌套**：优先早返回（Early Return），减少多层 `if`、`try`、`with` 嵌套。
4. **优先显式语法**：多用普通 `if/else/for/try/except/finally`，少用复杂推导式、三元表达式和隐式技巧。
5. **避免过度压缩**：宁可多写几行，也要把执行步骤和逻辑关系写清楚。
6. **中文注释**：注释和 Docstring 用简洁、准确的中文；解释目的、设计原因和关键逻辑，不重复代码表面意思。
7. **命名清晰**：变量、函数、类名直观，读者不需要反复跳转才能理解。
8. **保持原有功能**：优化结构时不随意删功能、改业务逻辑、改接口、改异常处理语义。
9. **谨慎处理复杂机制**：涉及异步、上下文传播、异常处理、资源释放、并发和数据安全时，优先保证正确性。
10. **控制优化范围**：不引入不必要依赖，不为形式上的架构整洁增加抽象层。

## 本项目的补充约定

- 现有 `ingest/index/retrieve/generate/eval` 的模块划分是合理的；“减少封装”针对微函数，不是把模块合成一个大文件。
- 旧代码不为了风格统一而重写；只改当前任务需要的范围。
- 正常开发直接改文件并给关键 diff；只有用户明确要求时才全文输出。
- 提交前必须跑 `python verify.py`，并检查没有把大体积评测 JSON/缓存提交进仓库。
