# Prompt A/B 报告（2026-11-02）

## 1. 实验设置

- 检索固定：`doc_cap=0`，K=20/20，混合 RRF + Cross-Encoder。
- 只改回答 prompt：
  - `v1`：原始 prompt（逐条列结论，无子问题结构约束）。
  - `v2`：逐子问题回答 + 每个小问必须单独成段 + 数值/期限/对象逐项写 + 引用只取标题行条款号。
- 生成：DeepSeek Flash，`max_tokens=1500`。
- L1 裁判：GLM 4.5 Air（同一裁判重判 v1/v2）。

## 2. L1 结果（共同 67 题）

| 方案 | 总覆盖 | 整题全中 | fact | multi | stale |
|---|---:|---:|---:|---:|---:|
| v1 prompt | 0.7756 | 0.5821 | 0.939 / 0.821 | 0.6125 / 0.375 | 0.7674 / 0.467 |
| v2 旧 prompt（第一版） | 0.7512 | 0.5373 | 0.939 / 0.821 | 0.5500 / 0.208 | 0.7674 / 0.533 |
| **v2 prompt 第二版（采用）** | **0.8146** | **0.5821** | 0.939 / 0.821 | **0.7125 / 0.375** | 0.7674 / 0.467 |

（每格为 coverage / full）

- 相对 v1：总覆盖 **+3.6pp**，95% CI（-2.2, +9.3），**不显著**；整题全中差 0.0；multi **+10.0pp**，fact/stale 不变。
- 相对 v2 旧 prompt：总覆盖 **+5.5pp**，95% CI（0.0, +11.6）；整题全中 +4.5pp，95% CI（-4.5, +14.9），**不显著**；multi **+16.3pp**，fact 恢复到 v1 水平。
- 全量 68 题（含新增 1 条）：覆盖 0.8125、整题全中 0.5735、至少中一条 1.000。

## 3. 引用结果

| 方案 | 引用数 | verified | no_clause | conflict | unmatched | 文件级匹配 |
|---|---:|---:|---:|---:|---:|---:|
| v1 recheck | 398 | 368 (92.46%) | 25 | 4 (1.01%) | 1 | 99.75% |
| v2 旧 prompt | 380 | 343 (90.26%) | 20 | 17 (4.47%) | 0 | 100% |
| v2 prompt 第一版 | 197 | 126 (63.96%) | 70 | 1 (0.51%) | 0 | 100% |
| **v2 prompt 第二版（采用）** | 242 | **191 (78.93%)** | 50 | **1 (0.41%)** | 0 | **100%** |

- 第一版为了“不写错小节号”过度保守，35.5% 只写文件名；第二版强制“标题行有条款号就原样写”，verified 回到 78.93%，冲突仍只有 1 条。
- 与 v1 相比：v1 引用更多、clause 级更高（92.46%），但冲突率是第二版的 2.5 倍（1.01% vs 0.41%），且 v1 有 1 条 unmatched。第二版更稳。

## 4. 检索指标（参考）

v2 prompt 第二版全量：Recall@5 **1.000**、MRR **0.8343**、coverage **0.9632**、full **0.9265**。

注意：prompt 不参与检索；这里比 v2（0.9853/0.8294/0.8971）略高，主要来自 LLM 查询分析的 run-to-run 方差，不应归因于 prompt。

## 5. 结论

- **已采用 v2 prompt 为默认**（`Config.answer_prompt_version="v2"`）：multi L1 明显提升，fact/stale 不回退，条款冲突显著下降。
- 保留 `--prompt-version v1` 回退。
- 当前仍是**单次生成**，LLM 温度 0.1 会带来波动；典型如“工伤费率”题，L1 裁判把已写出三个要点的回答误判为 0。L1 应继续人工抽查。
